Inheriting Existing Models

Inheritance is a mechanism that allows us to modify an existing model (like adding new fields to a customer or a product) without changing the original Odoo files. In Odoo Community Edition, we use classic inheritance.

To inherit a model, we use the _inherit attribute instead of _name. If we use _inherit on an existing model name, Odoo will merge our new fields into the existing database table.

Note: _name creates a brand new table. _inherit modifies an existing table in place.

Adding a single field to a Product

The following code adds a simple ISBN field to the core Odoo product.template model.

models/product_template.py 
from odoo import models, fields

class ProductTemplate(models.Model):
    _inherit = 'product.template'

    isbn = fields.Char(string='ISBN', help='International Standard Book Number')
Tip: Always remember to add your new Python file to __init__.py!

Extending Business Logic

We can also modify how Odoo behaves when records are created, written (updated), or deleted. We do this by overriding methods.

When you override a method, you must call super(). This tells Odoo to run the original code first (like actually saving the record to the database), before or after running your custom code.

Overriding the write method

The code below overrides the write method to log a message whenever a product is updated.

models/product_template.py 
from odoo import models, fields

class ProductTemplate(models.Model):
    _inherit = 'product.template'

    def write(self, vals):
        # super() calls the original write method
        result = super(ProductTemplate, self).write(vals)
        
        # Now run our custom logic
        if 'isbn' in vals:
            print(f"ISBN was updated to {vals['isbn']}!")
            
        return result
Warning: The write method receives a dictionary called vals containing only the fields that were changed. Always return the result of super()!

Computed Fields

A computed field is a field whose value is calculated by a Python function instead of being manually typed by a user.

We use a decorator called @api.depends to tell Odoo when to recalculate the field. A decorator is just a special tag placed above a function that changes how the function behaves.

Dependency: A dependency is a field that our computed field relies on. If the dependency changes, our field recalculates.

A simple computed field

Here we add a field that checks if the product has an ISBN.

models/product_template.py 
from odoo import models, fields, api

class ProductTemplate(models.Model):
    _inherit = 'product.template'

    isbn = fields.Char(string='ISBN')
    has_isbn = fields.Boolean(string='Has ISBN?', compute='_compute_has_isbn')

    # The decorator tells Odoo to run this function if 'isbn' changes
    @api.depends('isbn')
    def _compute_has_isbn(self):
        for record in self:
            if record.isbn:
                record.has_isbn = True
            else:
                record.has_isbn = False
Danger: The _compute method runs on a recordset (a list of records). You must ALWAYS loop through self using for record in self:. If you don't, Odoo will crash with a Singleton error!
Gotcha: Recursive Compute Loops If your compute method modifies a field that is listed in @api.depends, Odoo will get stuck in an infinite loop. Never modify your dependencies inside the compute function!

Stored Fields

By default, computed fields are calculated "on the fly" when you open the page. They are not saved in the database.

If you want to search, group, or filter by a computed field, you must add store=True. This saves the value in the database, improving performance when searching millions of records.

Making it searchable

The code below makes our boolean field stored in the database.

models/product_template.py 
from odoo import models, fields, api

class ProductTemplate(models.Model):
    _inherit = 'product.template'

    isbn = fields.Char(string='ISBN')
    
    # Adding store=True makes this field searchable in List views!
    has_isbn = fields.Boolean(
        string='Has ISBN?', 
        compute='_compute_has_isbn', 
        store=True
    )
Note: A stored computed field only recalculates when its @api.depends fields change. A non-stored computed field recalculates every time the record is viewed on screen.

API Integration in Python

REST API: A REST API is a web address that returns raw data instead of a visual webpage. Applications use APIs to talk to each other.

JSON: JSON is a standard text format for data. It looks exactly like Python dictionaries and lists.

In Odoo, we use the requests library to fetch data from APIs. The requests.get() function calls a URL and returns a response object. The .json() method converts the API's raw text response into a standard Python dictionary.

Status Code: Every API response includes a status code (like 200 for Success, or 404 for Not Found). We check this to know if our request worked.

A basic API call

The code below calls a public API and prints the title of a book.

Example Code 
import requests

def get_book_info():
    # Call the API with a 5 second timeout
    response = requests.get('https://openlibrary.org/isbn/9780140328721.json', timeout=5)
    
    # 200 means OK (Success)
    if response.status_code == 200:
        # .json() turns the response text into a Python dictionary
        data = response.json()
        print("Book Title:", data.get('title'))
    else:
        print("Book not found!")
Warning: Unhandled API Timeouts Always use timeout=5 when calling external APIs. If the external server is down and you don't have a timeout, your entire Odoo server will freeze waiting for a response!

Practice: Public APIs to Explore

If you want to practice calling APIs on your own (perhaps by adding a custom button to the Employee form or a Customer profile), here are three great public APIs you can experiment with:

  • OpenWeather API: Get current weather data for any city. (Requires signing up for a free API key).
    requests.get('https://api.openweathermap.org/data/2.5/weather?q=London&appid=YOUR_KEY')
  • PokéAPI: A fun database of all Pokémon. Great for testing how to parse deeply nested JSON data. (No API key needed!)
    requests.get('https://pokeapi.co/api/v2/pokemon/pikachu')
  • Official Joke API: Fetch random programming jokes. Perfect for testing a simple API call.
    requests.get('https://official-joke-api.appspot.com/random_joke')

Hands-On: ISBN Validation

Let's build our practical feature. We will add an ISBN field to products, and automatically call the Open Library API to see if the book exists. If it does, we'll mark the ISBN as valid!

1. The Python Model

This adds our fields, our compute method, and a button action to manually trigger a fresh lookup.

models/product_template.py 
from odoo import models, fields, api
import requests

class ProductTemplate(models.Model):
    _inherit = 'product.template'

    isbn = fields.Char(string='ISBN')
    
    # Stored so we can filter by valid books
    isbn_valid = fields.Boolean(
        string='Is Valid Book?', 
        compute='_compute_isbn_valid', 
        store=True
    )

    @api.depends('isbn')
    def _compute_isbn_valid(self):
        for record in self:
            if not record.isbn:
                record.isbn_valid = False
                continue
                
            try:
                # Call the API
                url = f"https://openlibrary.org/isbn/{record.isbn}.json"
                response = requests.get(url, timeout=5)
                
                # If we get a 200 Success, the book exists!
                if response.status_code == 200:
                    record.isbn_valid = True
                else:
                    record.isbn_valid = False
                    
            except Exception as e:
                # Catch timeouts and network errors
                record.isbn_valid = False

    def action_check_isbn(self):
        """Called by a button to force a fresh API check."""
        for record in self:
            # We clear the field, which forces the compute method to run again
            record.isbn_valid = False
            record._compute_isbn_valid()

2. The XML View

We need to add our fields to the Product Form view. We use XPath to inject our fields right below the product's barcode.

views/product_template_views.xml 
<record id="view_product_template_form_inherit_isbn" model="ir.ui.view">
    <field name="name">product.template.form.inherit.isbn</field>
    <field name="model">product.template</field>
    <!-- We inherit the original Odoo view -->
    <field name="inherit_id" ref="product.product_template_only_form_view"/>
    <field name="arch" type="xml">
        
        <!-- Find the barcode field and insert our fields after it -->
        <xpath expr="//field[@name='barcode']" position="after">
            <field name="isbn"/>
            <field name="isbn_valid" readonly="1"/>
            <!-- A button to trigger the manual check -->
            <button name="action_check_isbn" type="object" string="Verify ISBN" class="btn-secondary"/>
        </xpath>
        
    </field>
</record>
How to test this feature:

  2. Open any Product (or create a new one).
  3. Type a valid ISBN into the new ISBN field (below the barcode).
  4. Save the record, or click the Verify ISBN button. The "Is Valid Book?" checkbox should automatically turn on!
