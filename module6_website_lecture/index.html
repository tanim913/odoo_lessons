Building public-facing pages, routing, and portal views in Odoo 19.

Website Basics & Module Structure

Odoo's architecture naturally follows the Model-View-Controller (MVC) pattern, even on the frontend. When building public-facing web pages, Odoo relies heavily on its website and portal core modules. To enable website capabilities in your custom module, you must explicitly declare these dependencies in your __manifest__.py.

Why 'portal' and 'website'?
  • website: Provides the routing, SEO tools, and the base website.layout QWeb template.
  • portal: Provides the standard `/my/home` interface (the customer portal) where users can log in and securely view their own records like Quotes, Invoices, or Tasks.

Manifest Configuration

quality_control/__manifest__.py 
    # The 'website' dependency allows our module to hook into the frontend.
    'depends': ['stock', 'account', 'website', 'portal'],

Controllers (@http.route)

In Odoo, Controllers are classes that extend http.Controller. They act as the "Controller" in MVC, mapping incoming URLs to Python functions using the @http.route decorator.

route='/my/path' The URL endpoint. Can be a string or a list of strings for multiple paths.
type='http' The type of request. Use 'http' for standard web pages and 'json' for AJAX/RPC calls.
auth='public' Authentication level: 'public' (anyone), 'user' (must be logged in), or 'none' (framework level).
website=True Tells Odoo to render the page within the active website's context (applying languages, themes, and menus).
methods=['POST'] Restricts the route to specific HTTP methods (e.g., only allow POST for form submissions).
quality_control/controllers/controllers.py 
from odoo import http
from odoo.http import request

class JobApplicationWebsite(http.Controller):
    
    # 1. Show the Form (GET Request)
    @http.route('/jobs/apply', type='http', auth='public', website=True)
    def job_application_form(self, **kw):
        # request.render points to the QWeb template XML ID.
        # The second argument is a dictionary of variables to pass to the template.
        return request.render('quality_control.job_application_form_template', {})

    # 2. Handle Form Submission (POST Request)
    @http.route('/jobs/submit', type='http', auth='public', website=True, methods=['POST'])
    def job_application_submit(self, **post):
        # We must use .sudo() here! 
        # Why? Because 'auth="public"' means the user is a guest. Guests do not have write access to the database.
        application = request.env['quality.job.application'].sudo().create({
            'name': post.get('name'),
            'email': post.get('email'),
            'phone': post.get('phone'),
        })
        # Pass the created application name back to the template
        return request.render('quality_control.job_application_success_template', {'name': application.name})

Templates & QWeb for Website

Once the controller gathers the data, it passes it to QWeb, Odoo's template engine. QWeb uses standard XML tags prefixed with t- to inject dynamic content.

Key QWeb Directives:
  • t-call="website.layout": Wraps your code in the standard Odoo header and footer.
  • t-esc="variable": Safely outputs a variable to the HTML (escapes script tags to prevent XSS).
  • t-if="condition": Conditionally renders a block of HTML.
  • t-foreach="records" t-as="record": Loops through a list or recordset.
quality_control/views/website_templates.xml 
<template id="job_application_form_template" name="Job Application Form">
    <t t-call="website.layout">
        <div id="wrap" class="container mt-5">
            <h3>Apply for QA Inspector</h3>
            <!-- The form action MUST match the @http.route in your controller -->
            <form action="/jobs/submit" method="post">
                <!-- CRITICAL: Always include csrf_token for POST forms to prevent Cross-Site Request Forgery -->
                <input type="hidden" name="csrf_token" t-att-value="request.csrf_token()"/>
                
                <label>Name</label>
                <input type="text" class="form-control mb-3" name="name" required="1"/>
                
                <label>Email</label>
                <input type="email" class="form-control mb-3" name="email" required="1"/>
                
                <label>Phone</label>
                <input type="text" class="form-control mb-3" name="phone"/>
                
                <button type="submit" class="btn btn-primary">Submit Application</button>
            </form>
        </div>
    </t>
</template>

Portal: Views & Security

Once a user applies, they might want to log in and check their application status. To provide this, we inject our module's data into Odoo's standard Customer Portal (`/my/home`).

1. Portal Security & Access Rights

Unlike public users, Portal users have accounts but they belong to the restricted base.group_portal group. We must explicitly grant them read access, but more importantly, we need a Record Rule to ensure they only see their own applications, not everyone else's.

quality_control/security/security.xml 
<record id="job_application_portal_rule" model="ir.rule">
    <field name="name">Portal users can only read their own applications</field>
    <field name="model_id" ref="model_quality_job_application"/>
    <!-- domain_force ensures the record's creator matches the logged-in user -->
    <field name="domain_force">[('create_uid', '=', user.id)]</field>
    <field name="groups" eval="[(4, ref('base.group_portal'))]"/>
</record>

2. Portal Controller Integration

By inheriting CustomerPortal, we can add a counter badge to the main portal dashboard and create a dedicated list view.

quality_control/controllers/controllers.py 
from odoo.addons.portal.controllers.portal import CustomerPortal

class PortalJobApplication(CustomerPortal):
    
    # Add to the Portal Home Counter
    def _prepare_home_portal_values(self, counters):
        values = super()._prepare_home_portal_values(counters)
        # Check if our counter should be rendered
        if 'job_count' in counters:
            values['job_count'] = request.env['quality.job.application'].search_count([])
        return values

    # Render the List View
    @http.route(['/my/applications', '/my/applications/page/<int:page>'], type='http', auth="user", website=True)
    def portal_my_applications(self, **kwargs):
        # The Record Rule we created earlier will automatically filter this search!
        applications = request.env['quality.job.application'].search([])
        return request.render("quality_control.portal_my_applications", {'applications': applications})

3. Portal View Template

We use standard Portal layout templates like portal.portal_layout, portal.portal_searchbar, and portal.portal_table to ensure our custom page matches the rest of the Odoo portal.

quality_control/views/website_templates.xml 
<template id="portal_my_applications" name="My Applications">
    <t t-call="portal.portal_layout">
        <t t-call="portal.portal_searchbar"/>
        
        <!-- Conditional rendering using t-if -->
        <t t-if="not applications">
            <p>You have no job applications yet.</p>
        </t>
        
        <t t-if="applications" t-call="portal.portal_table">
            <thead>
                <tr>
                    <th>Name</th>
                    <th>Email</th>
                    <th>Status</th>
                </tr>
            </thead>
            <tbody>
                <!-- Iteration using t-foreach -->
                <t t-foreach="applications" t-as="app">
                    <tr>
                        <!-- Output variables using t-field -->
                        <td><span t-field="app.name"/></td>
                        <td><span t-field="app.email"/></td>
                        <td><span t-field="app.state"/></td>
                    </tr>
                </t>
            </tbody>
        </t>
    </t>
</template>
